# 一次真实的排查

下面这段是照着 `SKILL.md` 走一遍的样子。症状是真的常见：手机昨天还能用，今天连不上。

## 用户说

> 手机连不上了，Clash Meta 显示已连接，但网页打不开。VPS 是 203.0.113.10，端口 443。

## 第一步：分清是哪一层

“显示已连接”是客户端自己说的，不代表数据出得去。先问三句：

- 服务端跑的是什么？（用户答：sing-box）
- 电脑上能用吗？（答：也不能）
- 症状是哪种？（答：完全打不开，不是慢）

电脑也不能，排除手机的问题。

## 第二步：测端口

在电脑上：

```powershell
Test-NetConnection 203.0.113.10 -Port 443
```

结果：`TcpTestSucceeded : False`。

到这一步，问题已经不在客户端了。

## 第三步：看 VPS

SSH 进去，跑 `scripts/vps-check.sh`。关键几行：

```
== 监听端口 ==
LISTEN 0 4096 127.0.0.1:8080 0.0.0.0:*
```

服务在跑，但只听 `127.0.0.1`，外面的连接进不来。

再看防火墙：

```
== 防火墙 ==
Status: inactive
```

防火墙没开，那就不是防火墙拦的。

## 第四步：结论

配置里 `listen` 写成了 `127.0.0.1`。改成 `0.0.0.0`，重启服务：

```bash
sed -i 's/"listen": "127.0.0.1"/"listen": "0.0.0.0"/' /etc/sing-box/config.json
systemctl restart sing-box
```

再测端口，通了。

---

## 另一种走向

如果端口通、服务也在听，事情就往别处去了：

| 下一步看到什么 | 说明 |
| --- | --- |
| 端口通，但 TLS 握手失败 | 证书或 SNI 不对，或者中间有人劫持 |
| 握手成功，网页还是打不开 | DNS，看客户端解析出来的地址 |
| 能上，只有个别网站不行 | 分流规则，切全局试一次 |
| 都能上，就是慢 | 线路，`mtr` 看丢包在哪一跳 |

## 这段想说明什么

排查不是猜。每一步都有一个能验证的结果，验完再走下一步。`scripts/` 里三个脚本干的就是这件事：把每一步的结果摆出来，省得来回问。
