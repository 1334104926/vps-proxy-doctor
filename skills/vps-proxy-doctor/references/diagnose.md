# 分层排查

从下往上查，别跳步。越往下越少人出问题，但越难修。

## 0. 先把症状归到一层

| 症状 | 从哪一层开始 |
| --- | --- |
| 手机完全连不上，开关代理没反应 | 2. 端口 |
| 能连，但网页一直转圈 | 5. DNS |
| 有的能开有的不能 | 6. 规则 |
| 能上，速度几百 KB | 7. 慢 |
| 昨天好用，今天突然不行 | 2. 端口，然后 3. 服务 |

## 1. VPS 本身活着吗

```bash
ssh root@<VPS>
uptime
```

进不去先看云厂商控制台，是不是欠费、关机、或者被停机。这一步排除掉，再谈代理。

顺手确认服务开机自启：

```bash
systemctl is-enabled xray      # 或 sing-box / mihomo
```

返回 `disabled` 的话，重启一次就没了。这个坑很常见。

## 2. 端口通不通

在客户端测：

```bash
nc -vz <VPS> 443           # Linux/macOS
Test-NetConnection <VPS> -Port 443   # Windows
```

不通的话，在 VPS 上确认有没有在听：

```bash
ss -lntp | grep 443
```

**三层都要看：**

1. 服务有没有监听那个端口
2. 系统防火墙（`ufw status`、`nft list ruleset`）
3. 云厂商的安全组，在网页控制台，跟系统防火墙是两回事

**端口被封的特征**：国内连不上，用海外的机器或者在线端口检测工具能连上。这种情况换端口，别用 1080、8388、1081 这类一眼就能认出来的端口，换 443 或 8443。

## 3. 服务在跑吗

```bash
systemctl status xray --no-pager
journalctl -u xray -n 50 --no-pager
```

先看日志里的报错，别看配置文件猜。

配置语法检查：

```bash
xray -test -c /usr/local/etc/xray/config.json
sing-box check -c /etc/sing-box/config.json
```

## 4. 时间对不对

```bash
timedatectl
```

偏差超过 2 分钟，VMess 和 TLS 都会失败，现象是“能连上但立刻断”。

```bash
timedatectl set-ntp true
```

## 5. DNS

客户端解析出来的地址不对，流量根本到不了 VPS。

- Clash 系：看配置里的 `dns` 段和 `fake-ip` 设置。
- 手机：私人 DNS 开着的话，可能绕过了 Clash 的 DNS。
- 对比测试：同一个域名，在本机 `nslookup` 和在 VPS 上 `dig`，结果差太远就是有问题。

污染的特征：返回 `0.0.0.0`、`127.0.0.1`，或者一个明显不属于该站的 IP。

## 6. 规则

最快的判断：把代理切成全局模式，再开一次网页。

- 全局能开，规则不能开，问题在分流规则。
- Clash 的“连接”页面能看到每个连接命中了哪条规则，直接看。

常见误杀：

- `GEOIP,CN,DIRECT` 把目标站的 CDN 节点判成了国内。
- 域名规则写在 IP 规则后面，永远匹配不到。
- `final` 指向 DIRECT。

## 7. 慢

按这个顺序排除：

1. **线路**。VPS 在哪个机房、回程走哪家。`mtr -rw <VPS>` 看丢包在哪一跳。
2. **CPU**。小机器上 AES 很吃 CPU，`top` 看一眼。换 chacha20 会轻一些。
3. **晚高峰**。晚上八点到十一点慢、白天正常，就是国际出口拥塞，换机房比换协议有用。
4. **是不是走了中转**。中转有额外一跳，未必更快。

## 常见结论对照

| 现象 | 结论 | 怎么办 |
| --- | --- | --- |
| SSH 能进，代理端口不通 | 端口被封或防火墙 | 换端口，查安全组 |
| 端口通，客户端立刻断 | 时间偏差或 UUID 不对 | 对时间，核对服务端参数 |
| 能连，网页转圈 | DNS | 改 Clash 的 dns 段 |
| 部分网站不行 | 规则误杀 | 切全局验证 |
| 全部正常但慢 | 线路 | 换机房 |
| 换 IP 后好了，几天又不行 | 整段被封 | 换机房，别只换 IP |
